## 学习内容

### 模块：大语言模型（LLM）

**来源：** [Handbook LLM 章节](https://aiweb3.school/zh/handbook/ai/llm/)

#### 核心认知

> LLM 生成的是概率上合理的输出，而不是天然可信的事实。

这决定了 LLM 在严肃系统里的位置：它可以帮你理解、归纳、生成和规划，但不能单独承担事实来源、权限判断和最终执行。

#### 三个第一性原理

1. **把模型当推理层，不当真相源**：关键事实必须来自数据库、API、日志、文档源或其他可信系统。
2. **输出变成可检查对象**：摘要、分类、计划和操作建议都应该尽量落成 schema、参数、引用或日志。
3. **不确定性前移暴露**：模型不知道、资料过期、上下文不足时，要让系统显式降级。

#### 五个关键概念

| 概念 | 理解 |
|------|------|
| **Token** | 模型处理文本的基本单位。中文每个字 1-2 token，代码和 JSON 更吃 token |
| **Embedding** | 把文本映射成向量，用于语义搜索——适合找相关材料，不适合判断结论正确性 |
| **Transformer** | 核心架构，靠 Attention 在上下文中找模式。擅长组合信息，不等于有数据库 |
| **Hallucination** | 编造看起来合理的内容。处理不能只靠 prompt，要加外部校验 |
| **Multimodal** | 能处理文本+图片+代码截图，但关键判断仍要回到结构化数据 |

#### AI x Web3 中的位置

LLM 位于系统的**理解和生成层**。完整的 AI x Web3 产品还需要：
- 数据层：RPC、索引器、预言机、向量库
- 编排层：Prompt、Context、RAG、Agent workflow
- 执行层：工具调用、钱包、合约交互
- 安全层：Guard、Simulation、权限策略、人工确认

#### 最小实践

做一个"交易解释器"——输入交易哈希，让系统读取交易详情 + 事件日志 + 合约 ABI，然后 LLM 生成解释。要求把**模型生成、链上事实、来源边界、不确定性**分开。
